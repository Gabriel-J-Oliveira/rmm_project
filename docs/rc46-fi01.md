# RC46 FI-01 — bootstrap

O bootstrap de deployment reaproveita o bundle de confiança em TEMP somente
quando seu SHA-256 coincide com a metadata HTTPS; caso contrário baixa para
arquivo temporário, confere o hash e substitui o cache. Falha de download ou
hash não usa o arquivo antigo. A verificação assinada do pacote pelo instalador
permanece inalterada. Uma repetição com bundle válido elimina uma transferência
do bundle; não foi medido tempo ou volume real. Isso não é cache de pacote.

O caminho WinRM já recusa serviço ou executável existente antes de baixar o
instalador e distingue serviço, enrollment e heartbeat. No bootstrap de
deployment, `completed` ainda deriva do retorno do instalador e serviço em
execução; não comprova heartbeat independente. O callback atual aceita essa
declaração, portanto a conclusão operacional não está diferenciada de forma
completa. A confirmação por heartbeat, o reaproveitamento seguro de pacotes e
o reconhecimento de instalação saudável no bootstrap de deployment permanecem
pendentes; não houve alteração de contrato ou instalação em endpoints.
