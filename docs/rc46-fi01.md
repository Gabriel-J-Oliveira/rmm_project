# RC46 FI-01 — bootstrap

O bootstrap de deployment reaproveita o bundle de confiança em TEMP somente
quando seu SHA-256 coincide com a metadata HTTPS; caso contrário baixa para
arquivo temporário, confere o hash e substitui o cache. Falha de download ou
hash não usa o arquivo antigo. A verificação assinada do pacote pelo instalador
permanece inalterada. Uma repetição com bundle válido elimina uma transferência
do bundle; não foi medido tempo ou volume real. Isso não é cache de pacote.

O caminho WinRM já recusa serviço ou executável existente antes de baixar o
instalador e distingue serviço, enrollment e heartbeat. No bootstrap de
deployment, `completed` ainda deriva do retorno do instalador e serviço em
execução; não comprova heartbeat independente. O callback atual aceita essa
declaração, portanto a conclusão operacional não está diferenciada de forma
completa. A confirmação por heartbeat, o reaproveitamento seguro de pacotes e
o reconhecimento de instalação saudável no bootstrap de deployment permanecem
pendentes; não houve alteração de contrato ou instalação em endpoints.

## FI-01B

O instalador usa cache protegido por ACL existente, indexado pelo SHA-256
fixado; sem hash fixado continua baixando. Um mutex global serializa o acesso.
O arquivo é copiado para a área de trabalho e passa novamente por checksums,
manifesto, assinatura e metadata antes do uso. Após validação completa, um
arquivo temporário é publicado no cache por move/replace atômico. A assinatura
e os metadados são novamente baixados e verificados; extração continua sendo
necessária. Cache válido evita somente o download do ZIP.

O bootstrap classifica instalação ausente, incompleta, de outra versão,
não comprovada ou compatível. Só dispensa reinstalação quando serviço está
em execução, executável/configuração/identidade/estado existem, machine IDs
coincidem, token e servidor estão configurados, versão e SHA correspondem e
o checkpoint local de heartbeat bem-sucedido tem até dez minutos. Este
checkpoint é evidência local recente, não uma confirmação nova do backend.
Não há novo estado ou callback de heartbeat. FI-01C deve corrigir a confirmação
de conclusão pelo backend, que ainda aceita serviço executando como health.

Testes isolados cobrem cache válido e corrompido, falha de download, rejeição
de assinatura inválida pelo verificador RSA-PSS real e exclusão mútua entre
processos; não são dois installs reais simultâneos. Fixtures cobrem estados
locais e preservação da identidade. Não foi feita instalação corporativa.
